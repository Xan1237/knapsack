# Knapsack product requirements and acceptance criteria

Source: BUILD_PROMPT.md and design.md. Local application URL: http://127.0.0.1:3000.

## Packed suitcase and visual inspection
The dominant view is an actual interactive WebGL 3D open suitcase containing recognizable folded clothes, shoes, bottles, pouches and generic items. Initial sample inventory is explicitly labeled Demo inventory; it uses reproducible bundled fixtures, independently of live analysis. The traveler can orbit, zoom, reset the camera, select rendered objects, hide upper layers, explode the arrangement, and reveal items step by step with playback. A status label alone is insufficient: inspect the rendered scene and changes to visible objects. Reduced layer/step visibility never changes inclusion or solver inputs. Unplaced items remain visible outside the suitcase and listed by name and reason. The simulation estimates spatial fit and does not prove physical insertion feasibility or cloth behavior.

## Inventory correction and repacking
Select an item in the inventory or scene to rename it, make it bigger/smaller using a visual slider, optionally resize each axis, duplicate it, delete it, exclude it, change permitted rotations, or merge a suggested multiple-view match. Manual category additions are always available. No numerical measurements or model call are required to edit. Source photo thumbnails remain associated with items. Duplicates get unique stable IDs; merging combines sources while retaining the selected item's edits. A similar appearance is a merge suggestion only; identical physical belongings must not be merged automatically. Suitcase presets include personal, cabin, and checked sizes. Editing or changing suitcase triggers debounced worker repacking, visibly updates item size immediately, and invalidates old plans. Selection, identities, colors and overrides survive repacks. Every included item is accounted for once as placed or unplaced; excluded items are separately identified.

## Photo to packed suitcase
Users may upload multiple JPEG, PNG or WebP photos, max 6 MB each, up to 12 retained photos and 80 items. Explain before upload that live analysis sends photos to OpenAI and retains photos locally in this browser; the application server does not persist them. Show queued/analyzing/done/error progress per photo and a retry action. At most two photo analyses run at once. Live Responses API vision returns Zod-validated proposals: label, category, hex color, appearance and estimated millimeter dimensions, linked to source photo IDs. Data cannot become executable geometry. Review generated items beside the suitcase, correct sizes visually, and generate a validated packed plan. Preserve successful inventory when a photo fails and allow manual additions. Reject unsupported files and oversized uploads with useful feedback. Retries and stale completions do not duplicate proposals, overwrite edits or resurrect deleted proposals. Live smoke evidence must be distinct from deterministic demo regression evidence. Use bundled fixtures with explicit recognition expectations in public/fixtures/README.md. If credentials are absent, report configuration failure explicitly, never silently substitute demo analysis.

## Packing correctness and outcomes
Use a deterministic bounded heuristic in millimeters with allowed axis-aligned rotations and conservative wall/item clearance. Prefer supported lower placements. Independent validation checks finite positive dimensions, bounds, non-overlap, orientation/dimension agreement, unique identities and completeness. Associate every plan with all solver inputs including suitcase preset and clearance; discard stale results. Complete means all included items have validated placements. Partial layout, bounded search exhaustion, and direct constraints such as oversized envelopes or excessive total volume must be distinguished. Heuristic exhaustion never proves impossibility. Numerical diagnostics are optional details. Display meshes and solver envelopes scale consistently.

## Persistence, recovery and usability
Persist inventory, overrides, sources, photos and suitcase selection in IndexedDB across reloads. Restore source thumbnails and visual edits. Invalid/unavailable persistence produces a useful notice without crashing; reset session clears retained data and shows an empty inventory. Pending analyses interrupted by reload become retryable errors. Handle empty, computing, failed-analysis, invalid-plan and partial-packing states. Provide usable narrow-screen layout, accessible named controls and loading feedback. Clear selection/playback state when appropriate after resets or edits. Show a recoverable message if WebGL fails.

## Direct automated verification and honest reporting
Direct tests cover rotations, exact fits, clearance, overlap rejection, completeness, oversized items, invalid values, bounded-search outcomes, geometry scaling, stable IDs, retry idempotency, deleted proposals, stale analyses and stale plan acceptance. Typecheck, lint, tests and production build must pass. Browser requirements must be extracted and test files generated by Kane assurance commands, never hand-authored. Preserve replayable tests and report real coverage and gaps. Keep raw evidence ignored. Do not publish, deploy, push or submit.
