# Kane CI execution facts

These are execution facts for the seven app workflows already approved by the user. They do not introduce new product requirements.

- The base URL is supplied as the nonsecret variable `knapsack_base_url`. Open that URL plus `/pack`, or the base URL itself for the landing page. Do not hard-code a hostname or port in generated tests. Local and CI servers use the same application.
- The actual desktop application is the Next.js app in `final`. Its source is checked out independently of the Kane harness when testing a teammate's branch. The user requested fast PR checks and automatic repair in a separate run.
- Load demo restores nine named items and now selects Sage linen shirt in the item editor. Each demo row has a visible Demo label. Selecting any row opens its editor. Item size is a percentage range slider, 20 to 300; it is not a millimeter input. The shape controls are per-axis percentage sliders. The displayed percentage is the state that can be compared after reload.
- In an Astra modal the background inventory cannot be clicked. Closing or Keep my current list leaves inclusion unchanged. The advice remains cached for the same inventory revision when reopened. Apply selection is the explicit selection-changing action. Only changing geometry, bag, pins or inclusion invalidates a packing revision; changing an item's name alone is not sufficient. Use an actual geometry or inclusion change for stale-advice checks.
- For live Astra, the browser sends POST `/api/astra/suggest`, which should return HTTP 200. Inspect the request in the same action step that sends it. Inspect visible preview and keep/leave names separately from the unchanged background selection. Never ask for or send a provider credential to browser variables.
- Try a sample photo sends the real pump-bottle image through POST `/api/analyze`. Verify this concrete request's HTTP 200 response in the same action step. Verify photo-derived inventory and source association through the visible inventory/editor. A browser does not prove the server's upstream provider implementation; direct server and live API checks cover that boundary.
- The nonsecret variable `knapsack_collection_fixture` contains the full absolute path to the existing step2 JSON fixture, `final/public/example-collection.json`. Import collection is a file input; select/upload the actual file rather than stopping at the file chooser. The imported bag is My weekend bag, and the five items are from that JSON. Hidden geometry conversions and stable-ID preservation are direct-test responsibilities, not inferred from visible row presence.
- Save packing plan submits a native form POST to `/api/packing/export`. The response is JSON with HTTP 200 and `Content-Disposition: attachment; filename="knapsack-final-plan.json"`. Observe this request/response and the download-started confirmation in the same step as clicking Save packing plan. Do not inspect a downloaded file's bytes or hash through browser automation.
- The smallest personal suitcase is The light traveler. Make room protects essential pins and does not change inclusion until a swap or Leave out is explicitly selected. Use the nine-item demo as the reproducible overflow input. Full chosen-item accounting and a bounded-search explanation are visible.
- The 3D scene has controls for selection, orbit, zoom, reset, Top view, Peek inside, Exploded view, and Play packing order. First establish a complete current packing result before acting on the scene. Prefer concise, independent assertions that a browser can observe; do not claim global optimality or exact physical insertion.
- Try a 3D model collection loads `public/example-models.json` and its original glTF item and bag assets. This is a separate native millimeter/Z-up fixture. Keep imported-model checks distinct from the step2 centimeter/Y-up fixture.
- The UI is tested in desktop Chrome. The server's OpenAI key is supplied only to the server environment for the live suite. Core demo, overflow, 3D, import and export checks do not need OpenAI credentials.
