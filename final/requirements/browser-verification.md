# Current combined app browser verification

The user requests full browser verification of Knapsack's current combined app, including the actual photo-to-packed-result journey. Target desktop Chrome at http://127.0.0.1:3000. Existing smoke and overflow tests are in ../../testing/kane and are being executed separately. This document covers the remaining product journeys, not internal implementation proofs.

## Photo, geometry, and persistence

A traveler starts a clean trip, uploads the bundled pump-bottle photo (or uses Try a sample photo), and receives real Astra-generated geometry with an Astra 3D label and source photo. Analysis can take up to 150 seconds. The selected object's editor displays the same recognizable mesh. Resizing updates its estimated dimensions while preserving the mesh. Reload restores the edited object, mesh, source photo and inventory. This must use the real configured provider, with no synthetic analysis response.

## Inventory editing and reset

A traveler can add a manual item, rename it, duplicate it, delete the duplicate, and retain the original. Similar belongings remain separate unless the traveler explicitly merges them. A confirmed Reset trip clears inventory and stored photos, and a reload does not restore the cleared trip.

## Spatial inspection and correction

Load demo provides nine labeled travel objects in a two-compartment suitcase. Both compartments contain items. Selecting an item connects the inventory row to the editor and scene. The traveler can change size, permitted orientations and clothing compression, and inspect the updated packing result. Move items permits manual repositioning and Auto arrange returns to automatic placement. The display accounts for all included objects as placed or outside the suitcase.

## Playback and landing

Packing playback ends by closing the suitcase. Open suitcase restores both compartments for inspection. Layer inspection and exploded view remain usable. The current landing page intentionally shows a single compartment with eight sequential arrivals as the user scrolls; reverse scrolling reverses that sequence. Its packing link opens /pack. The old two-sided landing closure requirement is superseded by this current single-compartment design.

## Export and import

Save packing plan downloads the current inventory and plan as JSON. The export preserves edited dimensions, stable item IDs, essential flags, generated mesh and source provenance where present. Import collection accepts the provided step2 centimeter/Y-up fixture at ../testing/kane/fixtures/step2-collection.json (resolved from final), converting to millimeter/Z-up exactly once. Re-export and re-import preserve the item's displayed dimensions.

## Advice and revision

Real Ask Astra advice offers keep/leave choices and a validated preview. Essential items are not suggested for removal. Applying the preview updates the included selection only after explicit Apply selection. Changing inventory invalidates previously generated advice so stale choices cannot overwrite newer work. A provider error is shown without destroying inventory.

## Narrow layout and photo errors

At a narrow desktop viewport, the workspace retains accessible inventory controls and a usable scene without page-level horizontal overflow. Unsupported file types and photos over 6 MB produce an actionable rejection without adding invalid inventory. Manual additions remain usable after an upload rejection.

## Limits

Do not equate visual checks with physical packing or prove arbitrary race conditions through ordinary browser actions. Report platform limitations and unexercised failure injection separately. Tests must be generated by Kane assurance and preserve meaningful assertions; do not weaken assertions to manufacture a pass.
